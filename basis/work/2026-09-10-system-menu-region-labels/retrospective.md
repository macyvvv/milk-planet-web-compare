# Retrospective

## Observed event

The system submenu mixed two labels with `｜新宿`, several bare brand names, and overseas names containing English region tokens. The first uniform suffix implementation exposed mobile word fragmentation in the actual submenu width.

## Detection phase

Detected during Observe / Orient from the user's visual consistency review and comparison with existing store page location evidence.

## Missed gate or cause

The original submenu task focused on direct navigation and preserved the pre-existing partial label set without defining a display naming policy.

## Generalizable rule

Shared navigation labels need an explicit naming policy before implementation. Separate the official identifier from optional disambiguating region metadata, then validate the resulting strings in the actual submenu width. If the metadata creates word fragmentation or repeats an identifier's existing region, prefer the consistent identifier-only rule for the whole group.

## Skill or validator change

No Skill change is required in this packet; the shared-base consumer and selector audit rules already cover the cross-page impact. This packet records the repo-specific naming decision and its browser-driven fallback.

## Follow-up

If future navigation groups need the same metadata, evaluate a shared store metadata source rather than duplicating labels in each script.
