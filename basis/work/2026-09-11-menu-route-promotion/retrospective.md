# Retrospective

## Observed event

FACT: 11店舗の画像版を`index_0.html`へ保存し、HTML版を既存の`menu/index.html`へ配置した。移動後に相対パスを補正し、静的契約検証と3幅のブラウザ確認で新ページの到達、画像読込、横幅を確認した。

## Detection phase

FACT: Observeでは旧画像版、既存HTML候補、店舗別variant、共通CSS/JSと画像を棚卸しした。Orientでは公開URLを維持しつつ画像版を退避する方針と、`menu-html`からの相対パス差分を整理した。Decideで11店舗の昇格対象とShandy / Shinjuku / Meltyの最大番号variant採用を確定し、Actでリネーム・配置・パス補正を実施した。Checkでは初回のキャッシュ済み旧ページ結果を不採用とし、キャッシュバスター付きページを再監査した。Learnでは画像版保存とHTML版昇格を同一作業単位にし、静的検証をブラウザ監査前のゲートにする必要を確認した。

## Missed gate or cause

新しいルートへHTMLを配置するときの相対パス差分と、画像版を正本として保存する手順を同時に扱った。ブラウザの初回確認ではキャッシュにより旧画像版が表示され、監査ハーネスの失敗とページの失敗を分離する必要が明確になった。キャッシュバスター付きで再確認し、旧画像版由来の`index.png` 404と新HTML版の参照不備を切り分けた。

## Generalizable rule

画像版正本の保存、移動先相対パスの変換、既存variantの最大番号確認、配置後の全幅監査を一つの変更単位として扱う。

## Skill or validator change

既存の哲学学習ゲートと横断監査手順を適用した。今回得た一般則は監査記録へ反映し、相対パス変換、キャッシュバスター、画像版退避を今後の作業パケットの必須確認項目として扱う。新規Skillやvalidatorの追加は、同じ欠陥が再発した場合に限定する。
