# 権限マトリクス(ロール × 店舗スコープ × 操作)

## 0. 判定モデル

すべての書き込み・閲覧操作は、サーバー側で以下の順に検証する(REQ-ROLE-003)。

1. **認証済みか**(セッション有効性)
2. **ロールを持つか**(`user_roles`、`revoked_at IS NULL`)
3. **店舗スコープに含まれるか**
   - CAST: 対象データの `user_id` が自分自身か
   - STORE_MANAGER / STORE_DEPUTY_MANAGER: 対象データの `store_id` が `manager_store_scopes`(有効なもの)に
     含まれるか
   - AREA_MANAGER / SUPER_USER: 全店舗OK
4. **状態がその操作を許すか**(`state_transitions.md` のガード条件。例: 締切後はCASTの編集不可)
5. **入力検証**(`requirements.md` REQ-VALIDに従う)

クライアント側の表示制御(メニューを隠す等)はUXのためであり、2〜4はAPI/Server Function側で必ず再検証する。

## 2. データ閲覧スコープの実装原則

- 一覧・詳細取得の全クエリは、`WHERE store_id = ANY(:managerStoreIds)` のようにスコープをサーバー側で
  必ず結合する。クライアントから送られた `store_id` をそのまま信用しない(REQ-VALID「権限外店舗の操作」)。
- CASTの自分専用データ取得は `WHERE user_id = :sessionUserId` を必ず付与し、リクエストパラメータの `user_id`
  を信用しない(改ざんされたuser_idの拒否)。
