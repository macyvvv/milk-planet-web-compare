# 画面仕様(骨子)

> **本資料は骨子のみ(D-000)。承認後、各画面ごとの入力項目・バリデーション・遷移条件・エラー表示位置を
> 詳細化する。** ここでは画面一覧・責務・主要な操作補助・URL構造案のみを定義し、`requirements.md` REQ-SCREEN-001
> の元となる骨組みを示す。

## 1. 画面責務の原則

- 1画面1責務。単一の巨大テーブルへ全機能を詰め込まない(元指示書20.3)。
- 進捗確認(ダッシュボード/提出状況)・調整(確定シフト編集)・差分(差分一覧)・公開(公開/公開後変更)を
  画面として分離する。
- 日付別ビューとキャスト別ビューは表示切替であり、保存ロジック(サービス層関数)を共有する(REQ-ADMIN-003)。

## 4. 承認後に詳細化する項目

- 各画面の入力フィールド単位のバリデーションルール(`requirements.md` REQ-VALIDとの対応表)
- 画面遷移図(正常系・異常系)
- モバイル/PCでのレイアウト差分(PC専用機能は作らない前提での「PC幅を活用する」範囲の具体化)
- アクセシビリティ要件(フォーカス順序、ARIA属性、コントラスト比)
