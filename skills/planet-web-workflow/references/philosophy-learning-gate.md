# Philosophy learning gate

この参照資料は、Planet系ページのSkill改善または複数ページ監査で、見た目の模倣ではなく判断原理を学習・再利用するときに読む。

## Philosophy is not camouflage

「AIらしく見えない装飾」を目的にしない。学習対象は、利用状況に根ざした優先順位、根拠のある非採用、引き受けたトレードオフ、店舗固有性と共通化の境界である。

自動検査は、哲学的に正しいことの証明ではなく、判断を壊す構造欠陥を早期に止める安全柵である。

## Required principle record

実装前に、次を短く記録する。

| Field | Required question |
| --- | --- |
| Principle under test | 今回検証する設計原理は何か。 |
| Situation | 誰が、何を知るために、どの環境で見るか。 |
| Outcome | 理解・判断・行動のどれを改善するか。 |
| Priority | 何を最優先し、何を犠牲にするか。 |
| Preserved asymmetry | 原版のどの不均衡・密度・固有表現を残すか。 |
| No-change option | 現状維持を含む代替案と、採用しなかった理由は何か。 |
| Transfer boundary | 他ページへ転用できる原理と、店舗固有の判断はどこで分かれるか。 |
| Unknown | 何が確認できず、どの条件で保留するか。 |

主要判断は`FACT`、`USER`、`CONSTRAINT`、`INFERENCE`、`UNKNOWN`のいずれかへ追跡する。`INFERENCE`だけの主要判断は採用せず、確認または保留へ戻す。

## Learning review after audit

監査後は、各指摘を次の3種類へ分類する。

- `LOCAL`: 対象店舗・対象画像だけの判断。Skillへ一般化しない。
- `STRUCTURAL`: 複数ページで再発する共通原因。Skillまたはvalidator候補。
- `UNKNOWN`: 正本・意図・運用責任が不足しており、推測で修正しない。

Skillへ昇格するには、観測事実、検出工程、前段で防げなかった理由、別ページでも成立する根拠、過剰一般化の反例を記録する。単一ページの好み、単一店舗の色、偶然の改行は昇格させない。

## Required audit questions

- 実装後も、実装前に定めた優先順位が残っているか。
- 原版の固有性を消して、共通カード・同じ余白・同じ列数へ平坦化していないか。
- 変更しない判断を、単なる未対応として誤認していないか。
- 修正理由が実装後に後付けされていないか。
- 変更の効果と失う価値を比較できるか。
- 別店舗へ適用したときに、原理として再現するか、単なるスキン交換になるか。

判断できない場合の完了状態は`保留`であり、もっともらしい動機や装飾で埋めない。
